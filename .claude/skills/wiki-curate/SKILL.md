# 위키 큐레이션 (책임자 보조)

> **발동 선언**: 이 스킬을 실행할 때 "wiki-curate 프로토콜 발동합니다"라고 선언하고, 실행 중·보고에서도 같은 명칭을 쓴다.

규칙의 원본은 `wiki/SCHEMA.md`다. 충돌하면 SCHEMA가 이긴다.

이 스킬의 수행 주체는 **위키 감사 에이전트**다. 서브에이전트(wiki-auditor)로 위임하든
메인 세션에서 직접 수행하든 **절차와 판정 기준은 이 스킬이 원본**이고 아래 그대로 따른다.
에이전트의 정체·도구 권한(tools allowlist)·권한 경계와 집행 시 판단 원칙은
`.claude/agents/wiki-auditor.md`가 정의한다 — sources 대조·격리·판정 재료까지가 에이전트의 몫이고,
처분(verified 승격·삭제 확정)은 사람이다.

**기록(record)과 개별 문서 검증은 이 스킬의 일이 아니다** — 유일한 기록 경로는 세션 중에
본문을 사용자에게 보여주고 승인받아 verified로 커밋하는 것이다(SCHEMA "기록 경로" 절).
사용자가 명시적으로 "이거 위키에 남겨줘"라고 하면 그것이 곧 세션 중 확인 절차다 —
본문을 보여주고 최종 승인을 받아 verified로 커밋하라.

이 스킬은 그 경로가 남긴 것들을 정리하는 **큐레이션**용이다. 모드는 둘: 분기 **review**와 **audit**.
시공 전 위키(SCHEMA `config.sections`가 비어 있음)는 큐레이션 대상이 아니다 — `/wiki-start`를 안내하라.

## review — 잔여 draft·만료 처분 (분기, 책임자 보조)

세션 중 승인을 받지 못하고 쌓인 draft(주로 자율 세션 산출물)를 처분한다.
처분 판정은 사람(책임자)이 한다. 에이전트는 판정 재료를 만들 뿐이다.

1. 대상 수집:
   ```bash
   grep -rl "status: draft" wiki/        # 승격 대기
   grep -rn "review_by:" wiki/           # 만료 확인 — 오늘 날짜와 비교
   ```
2. 각 문서에 대해: `sources`를 실제로 열어 내용과 대조하고, 문서당 3줄 요약을 만든다 —
   ① 주장 요지 ② sources와의 일치 여부(불일치 지점 명시) ③ 추천 처분(승격/수정 후 승격/삭제).
3. 전체 목록을 표로 제시하고 **사용자 판정을 기다린다.**
4. 판정에 따라 status 변경·삭제를 실행한다. 승격 시 `verified_by: <책임자>`를 기입하고,
   판정 사유는 커밋 제목에 남긴다 — 형식은 SCHEMA의 장부 형식:
   `wiki: 큐레이션 — <대상>: <요지> (승인: <책임자>)`. 수기 이력 파일은 없다 — git이 장부다.

## audit — 분기 점검

보고서만 만든다. 처분은 책임자가 한다.

- **고아 문서**: SCHEMA "유지보수" 절의 고아 정의(진입로 기준 — 자동 생성 색인은 진입로가 아니다)를 따른다
- **모순**: 같은 주제를 다루는 문서 간 상충 서술 (grep으로 주제 겹침 후보를 찾아 대조)
- **이벤트형 무효화**: `scripts/wiki-stale-check.py` 실행 — 문서 updated 이후 `sources`
  경로가 변경·소멸된 문서 목록. 재검토 대상일 뿐 자동 강등 아님 — 판정(내용 유효 →
  updated 갱신 / 무효 → 수정·격리)은 사람이 한다
- **자동화↔SCHEMA 정합**: 지난 분기의 SCHEMA 개정(`git log --oneline -- wiki/SCHEMA.md`)이
  자동화 — `scripts/wiki-lint.py`, 이 스킬 — 에 반영됐는지
  대조. 어긋난 자동화는 에러 없이 구식 규칙을 조용히 집행한다.
- **형식 위반**: `scripts/wiki-lint.py --check` 실행 결과 확인 (pre-commit을 우회해 들어온 위반 탐지)
- **자동화 생존**: `git config core.hooksPath`가 `scripts/githooks`인지 확인 — 훅이 꺼져 있으면
  위반이 조용히 들어온다
- **규모**: 전체 문서 수 (~50 초과 시 통합·삭제 후보 제시)
