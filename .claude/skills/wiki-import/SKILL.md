# 기존 문서 위키 이식

> **발동 선언**: 이 스킬을 실행할 때 "wiki-import 프로토콜 발동합니다"라고 선언하고,
> 실행 중·보고에서도 같은 명칭을 쓴다.

규칙의 원본은 `wiki/SCHEMA.md`다 — 먼저 읽고, 이 스킬과 충돌하면 SCHEMA가 이긴다.
시공 전(config.sections 비어 있음)이면 기록할 수 없다 — `/wiki-start`를 먼저 안내하라.

**대원칙: 이식은 복사가 아니라 증류다.** 원본 문서가 존재한다는 사실은 이식 사유가 아니다 —
SCHEMA 기록 트리거를 통과한 지식만 위키에 들어간다. 작업 로그의 세션 서사("우리가 X를 했다")는
지식("X는 이렇게 동작한다")으로 바꿔 옮긴다.

## 절차

### 1. 인벤토리 — 코퍼스 전수 훑기

- 대상 디렉토리·파일을 전수로 읽고 파일별 분류표를 제시한다:
  **이식 소재** / **제외**(+사유 — 완료된 계획, 에이전트 설정, 일회성 진행 상태 등).
- 비텍스트 자산(이미지·스크립트·데이터)은 이식하지 않는다 — 필요하면 위키 문서의
  `sources`가 원 위치를 가리킨다.

### 2. 인터뷰 — 배치와 증류 강도

사용자에게 두 가지를 묻는다 (자율 세션이면 아래 "자율 세션이면" 참조):

**배치** — 이 지식 뭉치가 어느 방(섹션)에 들어가는가. 위키는 하나이므로 갈래는 섹션 선택뿐이다:
SCHEMA `config.sections`와 "프로젝트 규약" 절의 배치 기준으로 후보 섹션을 제시하고 고르게 한다.
기존 섹션 어디에도 안 맞으면 새 섹션 신설이 아니라 **범위 축소·증류 강화**를 먼저 검토한다
(섹션 변경은 `/wiki-start` 재시공의 일이다).

- 문서 예산(SCHEMA "크기 상한")에 이식분이 들어가는지 여기서 확인한다.
  초과 전망이면 증류 강도를 높이거나 범위를 줄인다.

**증류 강도** — 매핑 설계의 기본값:

- **강한 증류 (권장 기본)**: 파일 경계를 무시하고 지식 단위로 재구성·병합한다.
  같은 사실이 여러 파일에 있으면 최신 기록이 이긴다. 문서 수 최소.
- **보존 이식**: 원본 문서 단위를 유지한다(문서당 1건, 형식만 SCHEMA에 맞춤).
  원본이 이미 지식 단위로 잘 쪼개진 경우(런북 모음 등)에 적합.
- 강도는 코퍼스 전체의 기본값이고, 3단계 매핑표에서 파일별 예외를 둘 수 있다.
- 어느 강도든 SCHEMA 상한(문서 300줄·예산)과 기록 트리거 필터가 이긴다 —
  보존 이식이라도 트리거 없는 문서는 이식하지 않는다.

### 3. 증류 재구성 — 매핑표

- 선택된 강도로 매핑표를 제시한다: 위키 문서 후보(제목·유형·섹션) ← 소재 파일들(경로).
- 유형 판정은 SCHEMA "문서 유형과 frontmatter", 섹션 배치는 시공이 채운 SCHEMA
  "프로젝트 규약" 절의 배치 기준을 따른다. 반복 실행할 절차는
  스킬 후보로 따로 표시한다 — 위키 아님.
- 사용자가 이식 범위를 고른다. **이 선택은 범위 합의일 뿐 승인이 아니다** — 본문 승인은 7단계.

### 4. 중복·삭제 기록 확인 — 후보마다

- `grep -ri "<키워드>" wiki/` — 기존 문서가 있으면 새 문서 대신 그 문서를 고친다
  (verified였다면 수정 시 draft 강등 — 7단계 승인으로 재승격).
- 삭제 이력 확인은 SCHEMA "삭제" 절의 명령대로 — 같은 주제의 삭제 사유가 여전히 유효하면 쓰지 않는다.

### 5. 민감 정보 스캔 — 전수, 3등급

위키 밖 문서는 3등급 규율 없이 쓰였다고 가정하고 소재 전체를 스캔한다:

- 🚫 크리덴셜 값과 힌트("비번 동일" 같은 재사용 사실 포함)·개인 계정/이메일·실데이터 →
  제거하거나 소재만 기록.
- ⚠️ 서버 IP·내부 URL·포트 → 기록 허용 (repo 영구 private 전제).
- gitleaks pre-commit이 최후 방어선이지만 통과가 면죄부는 아니다 —
  값이 아닌 민감 사실은 기계가 못 잡는다.

### 6. 작성 — SCHEMA 스펙 그대로

- frontmatter 필수 항목과 유형별 본문 형식은 SCHEMA 표를 따른다. `updated`는 이식일.
- `sources`: 원본 파일 경로(타 repo 형식 `<repo>/<경로>`) + 원본에 실측일이 있으면 병기.
- 에러 메시지·명령·로그는 표현을 다듬지 말고 원문 그대로 — 미래 세션의 grep 적중 지점이다.
- **연결 관례**(SCHEMA): 여러 문서로 쪼개지는 이식이면 개요 문서 1개를 허브로 삼고, 두 번째 문서부터
  커밋 전에 허브에 링크 1줄을 추가한다 — 이식은 다수 문서를 한 번에 만들므로 특히 잘 걸린다.

### 7. 승인·커밋 — wiki-record와 동일

- 승인: SCHEMA "기록 경로"의 승인 절차를 그대로 따른다 (wiki-record §4와 동일).
  이식 고유 차분 — 코퍼스 일괄 승인은 없다. **위키 문서 한 편씩** 끊어서 받는다.
- 커밋: `wiki: 기록 — <파일명>: <요지, 이식 출처 포함> (승인: <이름>)`.
  `index.md`는 wiki-lint가 재생성한다 — 직접 편집 금지.

### 8. 마무리 보고

- 이식 결과표(위키 문서 ← 원본)와 제외 목록·사유를 보고한다.
- 원본은 지우지 않는다 — 위키는 지도이고, 원본 처분은 원본 소유자의 일이다.

## 자율 세션이면

자율 세션(정의와 처리는 SCHEMA "자율 세션 예외", 커밋 표기는 wiki-record의 자율 차분과
동일)에서의 이 스킬 고유 차분 둘:
배치할 섹션이 지시에 명시돼 있고 그 섹션이 실존할 때만 진행한다(섹션 신설은 사용자 사안 — 중단).
증류 강도는 묻지 말고 강한 증류를 기본으로 한다.
