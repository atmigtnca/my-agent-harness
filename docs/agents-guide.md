# 스킬·서브에이전트 작성 규약 (agents-guide)

> `.claude/agents/*.md` 서브에이전트와 `.claude/skills/`·`.agents/skills/` 스킬을 만들 때의
> 규격 원본이다. **무엇을 어떤 구조로 쓰는가**만 다룬다.
> 언제 위임하는가·브리프 템플릿은 `docs/loop/loop-guide.md` §5가 원본이다 — 여기서 중복하지 않는다.
> 규약의 뼈대는 다른 하네스에서 검증된 역할 에이전트 규격을 이 템플릿 문맥으로 옮긴 것이다.

서브에이전트 파일은 두 부분으로 이루어진다: **frontmatter**(필수 `name`·`description`·`tools`,
선택 `model`)와 **본문**(그 에이전트에게 주입되는 프롬프트).

## 1. 본문 골격 6절

본문은 다음 6개 역할을 모두 담는다 — identity / goal / constraints / execution_loop /
success_criteria / output_contract.

- **identity**: 이 에이전트가 무엇인지 한 문단. 역할 경계를 여기서 못박는다.
- **goal**: 호출 1회로 달성해야 할 결과.
- **constraints**: 하지 말 것 — 범위 밖 수정, 커밋 금지, 비밀 취급 등.
- **execution_loop**: 실제 수행 순서. 검증 명령을 구체적으로 적는다.
- **success_criteria**: 무엇이 참이면 끝인지. 기계로 확인 가능하게.
- **output_contract**: 부모에게 무엇을 어떤 형식으로 돌려주는지.

절 제목 표기는 자유지만 6개 역할은 필수다.
**왜**: 고정 골격은 에이전트마다 구조를 재발명하는 비용과 감사 비용을 없앤다.

## 2. frontmatter `tools:` allowlist 필수

`tools:`를 생략하면 부모의 도구가 전부 상속되므로 생략은 금지다. allowlist는 런타임의 도구
실명과 정확히 일치해야 한다(`Read`·`Grep`·`Glob`·`Edit`·`Write`·`Bash`·`Agent`).

- **읽기 역할**(리뷰·비평·계획·감사)은 `Write`·`Edit`를 **제외**한다.
- **제한적 수정 역할**은 최소 도구(`Edit`)만 예외로 허용하고 `Write`는 제외한다.

**왜**: 강제는 프롬프트 문구가 아니라 **도구 미주입**이다. "수정하지 마라"라고 쓰는 것보다
수정 도구를 주지 않는 편이 확실하다.

## 3. 판정형 에이전트는 verdict enum

판정을 내리는 에이전트(리뷰어·검증자·게이트)는 결과를 **verdict enum**으로 반환한다.
기본값은 `OKAY` / `ITERATE` / `REJECT`이며, 도메인에 맞는 enum을 써도 되지만 **값 집합을
그 에이전트 문서에 못박아야** 한다.
**왜**: 부모가 판정을 파싱해 분기한다 — 자유 서술은 분기할 수 없다.

## 4. 구현형 에이전트는 보고 4필드

구현을 수행하는 에이전트는 완료 보고를 4필드로 고정한다 —
`changed_files` / `decisions` / `verification` / `blockers`.
**왜**: Advisor가 재검증(diff 열기·검증 재실행)에 곧장 진입할 수 있다.

## 5. receipt-only 반환

장문 산출물(보고서·설계 문서·대량 로그)은 **파일로 persist**하고, 부모에게는 요약과 경로만
돌려준다.
**왜**: 부모 컨텍스트 오염 방지. 부모는 필요할 때 그 경로를 열면 된다.
쓰기 도구가 없는 **조회형** 에이전트(판정도 구현도 아닌 열람·수집 역할 — 예: wiki-scout)는
persist 대신 **반환 분량 자체를 제한**한다: 관련도 상위 항목만 온전히 싣고 나머지는
목록으로 실어, 부모에게 범위 축소 재위임을 요청한다 — 목적(컨텍스트 오염 방지)은 같다.

## 6. model / effort 라우팅

`model`은 **선택 필드**다 — 생략하면 세션 모델을 상속하므로, 호출 시점에 무게를 정하고
싶은 에이전트(판정형 등)는 비워 두고 본문에 권장 티어를 주석으로 남기는 편이 낫다.
지정한다면 아래를 지킨다.

- Worker(구현형)는 Advisor보다 **한 티어 아래 최신 모델**을 쓴다(docs/harness-guide.md의 모델 지정 원칙).
  구체 모델명은 프로젝트가 정하므로 이 문서에 박지 않는다.
- 판정형은 추론 effort를 높게, 기계적 변환·수집 작업은 낮게 잡는다.

## 7. 비이식 항목 — 도입하지 않는다

원 출처 하네스에 있었지만 이 템플릿에 옮기지 않은 개념들이다.

- **bash 접두사 화이트리스트** → `tools` 층위의 이분 선택(주입/미주입)으로 대체한다.
- **tmux 워커 풀** → 런타임 지원이 없다.
- **claim-lease 태스크보드** → 태스크 선택은 Advisor가 features.json으로 한다.
- **모호성 수치 게이팅(0~100 점수·임계점)** → 도입하지 않는다. 대체는 두 층이다: 기계 판정 가능한
  문구는 `scripts/loop-lint.py` 휴리스틱이, 의미 판정은 항목별 verdict enum(전 항목 OKAY가 게이트 —
  loop-plan §5)이 맡는다. 총점·임계점은 숫자 옷을 입은 인상이라 게이트로 쓰지 않는다.

**왜**: 런타임 지원이 없는 개념을 프롬프트로 흉내 내면 강제력 없는 문구만 늘어난다.

## 8. 스킬 규약 — 정본 + 래퍼

스킬 한 벌은 두 파일이다: **정본** `.claude/skills/<name>/SKILL.md`에 본문 전부와 발동 선언을
두고, **래퍼** `.agents/skills/<name>/SKILL.md`는 정본 경로를 가리키기만 한다. 쌍은 불가분이다 —
한쪽만 있으면 런타임 하나에서 스킬이 사라진다.

**왜 래퍼가 얇아야 하나**: 복제된 두 벌은 반드시 어긋난다. 래퍼에 본문을 옮기지 마라.

구조 규칙(필수 필드·이름 일치·발동 선언의 위치·래퍼 줄 수 상한)의 본체는
`scripts/skill-lint.py`가 기계로 강제하니 여기 재열거하지 않는다 — 수치와 검사 항목은
그 스크립트가 원본이다(서브에이전트 파일의 `name`↔파일명 일치도 같은 lint가 본다 —
디렉토리·파일명이 런타임의 식별자라 불일치는 조용한 이름 갈림을 만든다).
스킬·서브에이전트를 만들고 고친 뒤 `python3 scripts/skill-lint.py`를 돌려라.

`description`에는 트리거(언제 이 스킬을 부르는가)와 인접 스킬과의 경계만 담는다 —
frontmatter는 모든 세션에 상시 로드되므로 본문 절차를 복제하면 순수 상시 비용이다.

## 적용 체크리스트

- [ ] frontmatter 필수 3필드(`name`·`description`·`tools`) 존재
- [ ] `description`에 위임 트리거(언제 이 에이전트를 부르는가)가 있다
- [ ] `tools` allowlist가 있고, 읽기 역할이면 `Write`·`Edit` 제외
- [ ] 본문에 골격 6절이 모두 있다
- [ ] 판정형이면 verdict enum, 구현형이면 보고 4필드를 명시
- [ ] 장문 산출물은 receipt-only(파일 경로 + 요약)
- [ ] `model`은 선택 — 지정했다면 위 §6 규약과 일치(생략 시 세션 모델 상속)
- [ ] 공용 자산이면 이름에 `my-` 접두사가 없다

## 문서 작성 기준

AGENTS.md·`docs/`·스킬 본문 등 **지시 자산**을 쓰고 고칠 때의 기준이다 — 이 절이 원본이고
AGENTS.md "에이전트 문서 규칙"은 여기를 가리킨다.

- **분량**: 파일당 200줄 이하. 줄마다 "이걸 지우면 에이전트가 실수하는가"를 물어
  아니면 지운다. 코드를 읽으면 알 수 있는 것과 자주 변하는 수치는 적지 않는다.
  지침은 검증 가능하게 구체적으로 ("검사해라" ✗ → "커밋 전 `scripts/wiki-lint.py --check`" ✓).
- **역할 분담**: 모든 세션에 필요한 사실·규칙 → AGENTS.md, 위임·거버넌스 상세 →
  `docs/harness-guide.md`, 깊은 지식·다단계 절차 → 위키·스킬, 매번 예외 없이 강제할 것 →
  훅·권한 deny. 문서는 권고일 뿐 강제가 아니다.
- **AGENTS.md 심화**: AGENTS.md가 한 절로 감당 못 하는 주제는 위키 knowledge로 옮기고
  거기엔 요약 한 줄 + 링크만 남긴다 (SCHEMA 기록 트리거 ⑤). 위키 대상이 아닌
  하네스 규약의 상세는 `docs/`가 원본이다 — 위 "역할 분담" 참조.
- **모순 정리**: 모순되는 규칙 두 개를 발견하면 즉시 정리한다.
- **스킬 저작**: 새 스킬을 만들 때는 **정본(`.claude/skills/`)의 SKILL.md 상단에만** 발동 선언
  정규형("<스킬명> 프로토콜 발동합니다")을 담은 절을 넣는다 — `.agents/`의 얇은 래퍼는 정본을
  가리킬 뿐이므로 대상이 아니다 (규격은 §8).
