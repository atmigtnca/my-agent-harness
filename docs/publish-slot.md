# 발행 슬롯 — 외부 발행 파이프라인을 꽂는 자리

> 이 템플릿에는 발행 기능이 **없다.** 대신 발행을 붙일 **자리와 규약**만 정의한다.
> 위키의 verified 문서를 블로그·사내 포털·문서 사이트 같은 외부 매체로 내보내는 파이프라인은
> 매체마다 다르므로, 이 하네스를 쓰는 프로젝트가 직접 구현한다. 이 문서는 그때 지켜야 할
> 계약이다 — 어디에 두고, 비밀을 어떻게 다루고, 무엇을 지우고, 무엇을 남기는가.

## 0. 제안·승인 타이밍 — 이 절이 원본

발행 제안·승인의 **타이밍**은 이 문서가 원본이다. AGENTS.md "에이전트 행동 수칙"은 여기를 가리키기만 한다.

- **제안은 원큐로 묶어라.** 위키 기록과 외부 발행 제안이 함께 걸리면 **위키 본문 전체 +
  발행 요약을 한 패키지, 한 번의 승인 라운드(원큐)**로 처리한다(항목별 가부 가능).
- 승인 후 커밋·발행·추적 기록(발행 식별자 등)은 추가 확인 없이 완주한 뒤 원 작업으로
  복귀한다 — 단계마다 되묻지 않는다. 위키 본문은 요약으로 대체할 수 없다.
- 발행 파이프라인 자체(대상 매체·도구)는 이 템플릿을 쓰는 프로젝트가 정의한다.

## 1. 위치 규약 — 무엇을 어디에 두는가

| 구성 요소 | 위치 | 규격 |
|---|---|---|
| 발행 스킬(절차) | `.claude/skills/<이름>/SKILL.md` (정본) + `.agents/skills/<이름>/SKILL.md` (래퍼) | `docs/agents-guide.md` "문서 작성 기준"·§8 준수 |
| 발행 CLI·스크립트 | `scripts/<파이프라인 이름>/` 전용 디렉토리 | `scripts/` 루트를 어지럽히지 않는다 — 위키 자동화 스크립트와 섞이지 않게 한 디렉토리에 모은다 |
| 매체 API 참조 | `docs/` 아래 문서 한 편 | 스킬 본문에 API 스펙을 복제하지 말고 이 문서를 가리킨다 |

스킬 쌍(정본+래퍼)이 어긋나면 `scripts/skill-lint.py`가 커밋을 막는다 — 발행 스킬도 예외가 아니다.

## 2. 비밀 취급 — 크리덴셜은 코드에 없다

- 매체의 **API 키·토큰은 `.env`에만** 둔다. `.env`는 gitignore 대상이고 사용자만 기입한다.
- **에이전트는 `.env`를 읽지 않는다.** 값을 소비하는 주체는 스크립트뿐이며, 에이전트는
  스크립트를 호출할 뿐 값을 보지 않는다. 권한 설정(`.claude/settings.json` deny)으로 막는 것이 확실하다.
- **크리덴셜 원문은 출력·문서·커밋 어디에도 남기지 않는다.** 디버깅 로그에 헤더를 통째로
  찍는 것이 대표적인 유출 경로다 — 마스킹하거나 찍지 않는다.
- 위키 문서에는 **소재만** 기록한다(`wiki/SCHEMA.md` "민감 정보 3등급"). gitleaks pre-commit·CI가 최후 방어선이다.

## 3. 세탁 원칙 — 안과 밖은 다른 글이다

위키는 내부용이라 내부 사실을 담는다. 외부 발행본은 그 사본이 아니라 **세탁을 거친 다른 글**이다.

- 제거 대상: 호스트명·서버 IP·내부 URL·경로, 실명(사람·팀), 비공개 수치(매출·용량·비용·규모),
  고객·거래처 식별자, 내부 시스템 코드네임.
- **기계 검사**: 발행 직전 금지어 목록을 `grep`으로 전수 검사해 0건을 확인한다. 금지어 목록은
  프로젝트가 자기 사정에 맞게 정의하고 발행 스크립트에 박아 둔다 — 사람의 눈은 반복 검사에 약하다.
- **사람 게이트**: 기계 검사는 필요조건일 뿐이다. 실질 게이트는 **사용자가 발행본 전문을 정독하고
  승인**하는 것이다. 승인 전 공개 발행은 금지 — 부득이하면 비공개(draft·private)로 올린 뒤 사용자가 공개한다.
- 세탁으로 글이 무너진다면(내부 사실이 논지의 뼈대라면) 그 문서는 **발행하지 않는다.** 억지로 익명화한
  글은 틀린 글이 되기 쉽다.

## 4. 발행 추적 — 한 번 나간 글은 갱신 대상이다

- 발행에 성공하면 원본 위키 문서 frontmatter에 **발행 식별자**를 기록한다 (예: `published_id: 128`).
  매체가 URL만 준다면 그 URL을 값으로 쓴다.
- 식별자가 있는 문서는 **재발행이 아니라 갱신** 대상이다 — 같은 글이 두 벌 올라가는 사고를 막는다.
- 식별자 기록까지가 발행 작업의 끝이다. 승인 → 발행 → 식별자 커밋을 한 흐름으로 완주한다.
- 프로젝트가 `published_id` 외의 필드를 쓰기로 했다면 이름과 의미를 `wiki/SCHEMA.md`
  "프로젝트 규약" 절에 적는다 — lint는 모르는 필드를 검사하지도 지우지도 않으므로,
  적어두지 않으면 아무도 규칙을 모르는 사문(私文)이 된다.

## 붙이기 전 체크리스트

- [ ] 발행 스킬 정본·래퍼 쌍이 있고 `scripts/skill-lint.py`를 통과한다
- [ ] 스크립트가 `scripts/` 아래 전용 디렉토리에 모여 있다
- [ ] 키는 `.env`에만 있고, 에이전트 권한에서 `.env` 읽기가 막혀 있다
- [ ] 금지어 목록이 정의되어 있고 발행 경로에서 기계로 검사된다
- [ ] 사용자 정독 승인 없이는 공개 발행이 불가능한 절차다
- [ ] 발행 성공 시 식별자를 원본 문서에 기록하고 커밋한다
